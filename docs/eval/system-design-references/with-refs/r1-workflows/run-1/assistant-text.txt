  1. Add a timeout to the model client and a call that writes the summary.
  2. Add metrics.
  3. Move storage to Firestore, with a record that counts usage against a daily limit.
  4. Add a client for a Cloud Tasks queue.
  5. Write the code that generates the five sections and then the summary.
  6. Add routes to create a report, check its progress and run the work.
  7. Update `deploy.sh` to deploy a second, private Cloud Run service and the queue.
- **Top assumptions:**
  - **The five sections need your choice (Q1).** The plan's default is company overview, financial health, market and competitive position, management and governance, and legal/regulatory/risk, with the executive summary written last from those five.
  - **Reports are generated in the background.** Creating a report returns a link in under a second, and the caller checks that link until the report is done. If one section keeps failing, the summary is written from the other four and the report is marked `partial`. The discovery step was only moderately confident about this choice.
- **Research:** Web research was skipped because this isn't a question the web can answer. You can force it with `flow feature create --research`.
- **Vetting verdict:** - **Verdict:** adopt-with-conditions: generation runs off the request path — creating a report answers in under 1 s with a status link, and a retried or redelivered section never calls the model again once its text is stored.

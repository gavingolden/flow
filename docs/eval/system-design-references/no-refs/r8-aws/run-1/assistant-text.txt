## Plan ready for review: `POST /reports`

The plan and PR description draft are written, and nothing else was changed. No source files were touched and no later phase was started. I checked that both files exist and aren't empty; I didn't read them myself.

**Main finding:** a request that waits for the report can't work here. Each model call takes 20–60 s, there are five of them, and API Gateway cuts every request off at 29 s. So the request would always time out, and the paid model calls it had started would still run and be billed.

- **Proposed design:** `POST /reports` replies with `202` and a report id within 10 s, without calling the model. Each of the five sections is then generated by its own task on a queue. The client polls the existing `GET /reports/{id}`, which reports `pending`, `complete` or `failed`.
- **Tasks:** 8. Three of them also fix things the new endpoint depends on:
  - Add the build/test setup that `npm test` and `npm run build` expect but that doesn't exist yet.
  - Give the model client in `src/llm.ts` a timeout and distinct error types.
  - Fix the existing GET endpoint, which is missing its table name, its read permission on `Reports` and a module import.
- **Follow-up issues:** 1 possible one, requiring an API key on `GET /reports/{id}`. It's left unticked as too minor for this PR.
- **Research:** web research was skipped because the timing limits that decide the design are already in the repo.

**Decisions:**
- **Which five sections:** the plan uses placeholders: `overview`, `products`, `market`, `financials`, `risks`.
- **Daily cap on accepted reports:** the placeholder is 100 a day, which means 500–1,500 model calls a day.
- **Async flow:** check that clients getting a `202` and polling for the finished report is acceptable to you.

The planning checks (`flow-plan-lint`, `flow-candidate-issues --lint`, `flow-test-steps-lint`) all passed.
